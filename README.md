# Machine Learning project specification

**Student template · English · approximately 2–3 pages**

Use this template for the initial Week 1 project specification. Teams must have **2–4 members; pairs are encouraged**. Project deliverables and presentations are in English. Keep the document concise: state your engineering problem, show that suitable data are available, define the ML task and baseline, and explain how you will evaluate it. The source asks for the ten headings below. Complete every heading; make the dataset link and source easy to open. Do not report results you have not measured. Mark unresolved feasibility questions so the team can check them early.

## 1. Project Title

Choose a concise title that names the application or problem. Avoid a title that promises a specific result before the experiments are run.

**Write:**

- Project title: `[Type here]`

## 2. Team Members

List every member's name. Add a short initial responsibility for each person so the work plan has a clear starting point. Responsibilities can change as the project develops.

**Write:**

- Names: `[List all team members]`
- Initial responsibilities: `[State the first task each member will own or share]`

## 3. Context and Motivation

Describe the engineering specialization and application domain. Explain why the problem matters to that context and who might use or interpret the result. Keep the motivation connected to the data and problem you can actually study.

**Write:**

- Application context: `[What field or engineering setting is this about?]`
- Motivation: `[Why is this problem worth studying?]`
- Intended user or decision context, if relevant: `[Who could use the result, and how?]`

## 4. Problem Statement

State one concrete problem and the main research question. Make the scope narrow enough to address within the project timeframe. Distinguish what the team wants to investigate from what it can establish with the selected data.

**Write:**

- Problem: `[What specific problem will the project address?]`
- Main question: `[Write one question the experiments can answer]`
- Scope or boundary: `[What is included, and what is outside the project?]`

## 5. Project Objectives

List a small set of observable objectives. An objective should describe something the team will produce or evaluate, rather than a promise that a model will achieve a particular score. Include a way to judge whether each objective is complete.

**Write:**

- Objective 1 and completion evidence: `[Type here]`
- Objective 2 and completion evidence: `[Type here]`
- Objective 3, if needed: `[Type here]`

## 6. Dataset Description

Give a direct link to the dataset and identify its source organization, repository, or publication. Describe what one row represents, the approximate number of observations, available features, data types, and the target if one exists. Note known missing values, quality limitations, access steps, usage restrictions, and licensing. Explain why these data can address the stated problem. If the group will collect or generate data, describe the process and why it is feasible.

**Write:**

- Dataset name and direct link: `[URL]`
- Source: `[Organization, repository, or publication]`
- Unit of observation and approximate size: `[What does one row represent? How many rows?]`
- Features, data types, and target/output: `[What is available?]`
- Suitability and known limitations: `[Why can this answer the question? What may be difficult?]`
- Access, license, or collection feasibility: `[What has the team checked?]`

## 7. Machine Learning Task

Name the task, such as classification, regression, clustering, anomaly detection, recommendation, computer vision, NLP, or time-series analysis. Identify the inputs and output. For supervised tasks, state where the target label or value comes from. Make sure the task agrees with the dataset description and project question.

**Write:**

- Task: `[Type here]`
- Inputs: `[Which features will the model use?]`
- Target or expected output: `[What should the method predict, group, rank, or detect?]`
- Measurable goal: `[What result would address the main question?]`

## 8. Baseline Strategy

Choose one simple, reproducible method appropriate for the task. Possible baselines include a majority or random classifier, simple statistical prediction, linear or logistic regression, a decision tree, or basic k-nearest neighbors. Explain why this is a fair reference and what later methods will be compared against. The baseline must be implemented before advanced models.

**Write:**

- Baseline algorithm: `[Type here]`
- Why it is appropriate: `[Connect it to the task and available data]`
- How it will be compared with later approaches: `[State the shared reference]`

## 9. Evaluation Strategy

Describe how the data will be divided into training, validation, and test sets, or give another justified validation approach. State the metrics and why they fit the task. Explain when preprocessing and model choices will be learned. If the data have time order, repeated entities, groups, or other dependencies, say how the split will avoid an unrealistic evaluation. Keep the final test data out of model and feature-selection choices.

**Write:**

- Split or validation plan: `[How will training, validation, and test data be formed?]`
- Metrics: `[Which measures will be reported, and why?]`
- Fit boundary: `[Which steps learn from training data? How will choices be made?]`
- Evaluation limitations: `[What uncertainty or data constraint should readers know?]`

## 10. Initial Work Plan

List the first tasks, their order, and how the work will be distributed among team members. Include the immediate data and baseline actions, dependencies, and a Week 1 check that will show whether the project remains feasible. Use the course's week sequence rather than inventing calendar dates.

**Write:**

- First tasks and order: `[List the initial work sequence]`
- Responsibilities: `[Who will lead or share each task?]`
- Week 1 feasibility check: `[What must be confirmed before moving on?]`
- Open questions: `[What will the team check next?]`

Before submitting, confirm that the source link works, all ten sections are present, the problem is supported by the data, the baseline is defined before advanced models, the evaluation plan protects held-out data, and the initial work plan has named responsibilities. Keep the final specification near the requested **2–3 pages** by removing repeated background rather than dropping a required decision.
